# Краткое состояние проекта

Обновлено: 7 ноября 2026. Основной контекст для продолжения разработки.

## Проект и поставка

- «Расписание процедур»: локальное оконное приложение Windows x64, Electron + JavaScript/HTML/CSS/Canvas, без UI-фреймворка. Для разработки Node.js 24 и npm.
- Рабочая папка: `E:\AA\Расписание процедур`. Публичный репозиторий: https://github.com/Surprisemm/procedure-planner.
- Публичный релиз — `v1.0.2`. Подробности — `CHANGELOG.md`; перед работой проверять `git status`.
- Последний проверенный переносимый файл: `Расписание процедур 1.0.2.exe` в корне. Один EXE, без установки и браузера. Он не подписан: SmartScreen может предупреждать об неизвестном издателе.
- Результат работы — **PNG**. Редактируемый проект — JSON. Интеграция с электронными таблицами не планируется.
- Пользовательские данные: `%APPDATA%\Расписание процедур`, `autosave.json`, `autosave.previous.json`, `window.json`. Миграция прежнего имени уже реализована. Эти данные не являются временными артефактами разработки.

## Принятое поведение

- Слева: отдельные именованные расписания/заезды; каждый содержит собственных пациентов и дни. Заезд по умолчанию — 28 календарных дней включительно. Список пациентов общий для всех дней своего расписания.
- Галочка пациента управляет участием в конкретном дне: скрывает колонку и удаляет все назначения пациента в этом дне, включая закреплённые. Повторное включение их не возвращает, отменить можно через Ctrl+Z. Назначения, скрытые старой версией, удаляются при включении и не копируются. Новые дни включают всех. Корзинки у пациентов и расписаний.
- Центр: вкладки дней, временная сетка, колонки пациентов. Копирование дня и отдельных назначений между датами.
- Слева вкладки «Пациенты» и «Инструктора»: инструктора — глобальный справочник проекта, только ID и ФИО, добавление по одному/списком, поиск, редактирование, удаление. Выбор действует по всей строке и сохраняет цель клика при blur-перерисовке ФИО. У процедуры список инструкторов через плюс в инспекторе: инструктор и цвет в одной строке. Цвет первого связан с «Фон» процедуры в обе стороны, у остальных свой: при добавлении равен цвету процедуры, дальше меняется независимо. Новое назначение получает первого инструктора, сменить его можно в инспекторе назначения, цвет меняется вместе с ним. На карточке библиотеки показан первый инструктор и «+N».
- Внизу: общая для всех расписаний библиотека заготовок процедур. Справа: инспектор выбранного объекта; при снятом выделении — свойства дня.
- Длительность процедуры в библиотеке кратна шагу сетки открытого дня, иначе ввод отклоняется. Смена шага дня уже созданные процедуры не меняет.
- Масштаб 50–200% рядом с вкладками меняет высоту сетки и ширину колонок только в рабочей области: сохранённая ширина и PNG не зависят от него. «Очистить расписание» рядом удаляет все назначения открытого дня, включая закреплённые, без подтверждения; Ctrl+Z возвращает.
- Колонки пациентов меняются местами перетаскиванием заголовка: соседние плавно сдвигаются вместе с блоками, порядок общий для всех дней расписания, левого списка и PNG, отменяется Ctrl+Z.
- Шаг сетки по умолчанию 5 минут, начало 09:00. Сетка расширяется по мере работы, календарная граница — 00:00–23:59 (1440 используется как исключающая граница в модели). Фиксированного конца рабочего дня нет; экспорт обрезает заданный диапазон.
- У новой заготовки есть поле длительности, начальное значение **50 минут**. Существующие встроенные заготовки могут иметь 55 минут. Правил для субботы нет.
- Перенос из библиотеки за центр, автопрокрутка отключена. Перенос/изменение размера назначения в таблице прокручивает сетку у края сразу, без задержки. Сверху блок привязывается к первой строке.
- Общие периоды — только визуальные полосы, назначения могут их пересекать. По умолчанию только обед 13:00–13:30; консилиум и свои периоды добавляются вручную. Полосы выделяются мышью, меняются только в инспекторе, не перетаскиваются. Подписи начинаются в колонке времени.
- Конфликты не запрещаются и не сопровождаются предупреждениями. Перекрывающиеся назначения располагаются рядом. Старые области ячеек сохранены для совместимости JSON, но не создаются, не показываются и не экспортируются.
- Оформление имени/домика/фона пациента относится к таблице и PNG. Левый список всегда использует стандартное оформление.
- Заготовка: единый раздел «Процедура»; название, оформление, цвета, длительность, затем флажок применения к текущему дню; ниже две кнопки действий. Без флажка меняется только заготовка. С флажком редактируемые свойства получают все назначения того же `procedureId` текущего дня; начало, пациент и остальные свойства сохраняются. Другие дни/заезды не затрагиваются. Флажок сбрасывается при смене выбора/дня. Одно изменение — одна отмена.
- Карточки библиотеки меняются местами перетаскиванием: остальные плавно сдвигаются, у края список прокручивается, порядок сохраняется и отменяется Ctrl+Z. Вынос за библиотеку на сетку ставит процедуру как раньше.
- Оформление заготовки отображается в библиотеке; новые назначения наследуют его. У карточки библиотеки при наведении и выборе справа сверху кнопки «Дублировать» (копия рядом, с пометкой «(копия)» в названии) и корзинка (с подтверждением, размещённые назначения сохраняются). У назначения при наведении и выборе корзинка справа сверху и замочек слева (закреплённый замочек виден всегда); используется обычное удаление, доступен Ctrl+Z.
- Время выбирается только в списках часов и минут: поле открывает их по клику, текст не вводится. Необязательные поля дают кнопку «Очистить».
- Цвета выбираются в popup с кнопкой «Готово», образцы по 8 в ряд, добавление плюсом и удаление через контекстное меню. Типографика только для видимых/экспортируемых текстов; заметки не форматируются.
- Синяя тема, единая шапка с оконными кнопками, корректное затемнение при диалогах. Минимум микропояснений. Обучение по ⓘ у названия программы — 10 страниц от создания расписания до PNG. Презентация автозаполнения — 10 страниц по ⓘ в заголовке его окна, закрытие возвращает к настройкам без потери правок. Скриншоты пересоздаются запуском с `--smoke-test --capture-tutorial` на отдельном профиле (`scripts/capture-tutorial.cjs`); новый файл добавлять в `FILES` в `desktop/main.cjs`.
- PNG: выбранные пациенты и диапазон времени, скруглённые блоки, заголовок с днём недели и датой, без подписи внизу. Конец по умолчанию — окончание последней процедуры включённых пациентов. Имя и время короткой полосы должны помещаться.

## Где находится логика

- `app.js` — UI, выбор, формы, транзакции, undo/redo и drag and drop. Поле инспектора сохраняется при уходе с него; перерисовка откладывается до конца клика (`holdRender`), чтобы клик дошёл до цели.
- `autofill.mjs` — генератор расписания; новый модуль renderer нужно добавлять в `FILES` в `desktop/main.cjs`.
- `domain.mjs` — модель, валидация, заезды/дни, копирование, участие пациентов, `updateProcedureTemplate`.
- `presentation.mjs`, `export.mjs` — стили, укладка текста и Canvas PNG.
- `color-picker.mjs`, `text-editors.mjs`, `time-picker.mjs`, `drag-scroll.mjs` — редакторы и прокрутка.
- `desktop/main.cjs`, `preload.cjs`, `storage.mjs` — оболочка, ограниченный IPC, атомарное сохранение и восстановление. Node.js в renderer не открыт, внешние сетевые запросы блокируются.
- `desktop/smoke.cjs`, `desktop/verify-*.cjs` — отдельные оконные проверки, загружаются только в тестовом режиме.
- `scripts/` — иконка, сборка, снимки для встроенного обучения. `assets/tutorial/` используется самим приложением; не удалять.

## Модель и проверки

Старые проекты при открытии переводятся один раз (`upgradeProcedureInstructors`): копии процедуры с одним названием объединяются в одну карточку, назначения и настройки автозаполнения перепривязываются, цвет копии становится цветом её инструктора, длительность берётся у первой копии.

JSON `version: 1`. Необязательный в старых файлах глобальный `instructors: [{id,name}]`; `instructors: [{instructorId,color}]` у процедур, `instructorId` у назначений, необязательный boolean `locked` у назначений. Удаление инструктора снимает ссылки во всех расписаниях, не удаляя назначения. Корень: `procedures`, текущие `patients`/`days`, `stays`, `currentStayId`; данные неактивных заездов хранятся внутри `stays`. Библиотека глобальная. День: `columns`, `appointments`, `bands`, `disabledPatientIds`, `start/end/step`. Назначение связано через `procedureId` и хранит собственные текст/цвет/длительность/стили. Стиль текста — `textStyles[key]`, шрифт, размер, bold/italic; старые поля поддерживаются.

- `Запустить актуальную версию.bat` в корне запускает текущий код без сборки, с обычными пользовательскими данными. Если EXE уже открыт, вместо нового запуска активируется он.
- `npm start` — разработка; `npm test` — 108 проверок модели, хранения и генератора, включая случайные настройки.
- `npm run build:desktop`, затем `npm run build:portable` — сборка единого EXE в `release/`.
- Оконные проверки: задать `RITM_SMOKE_DIR` в `artifacts/`, запустить Electron с `--smoke-test` и нужным флагом: `--smoke-autofill` (нужен `autosave.json` с копией тестового проекта в этой папке), `--smoke-procedure-card`, `--smoke-column-drag`, `--smoke-day-tools`, `--smoke-inspector-commit` (реальная мышь: каждое поле × каждая цель клика), `--smoke-monkey` (случайные действия, `RITM_MONKEY_SEEDS`, `RITM_MONKEY_STEPS`), `--smoke-inspector-layout`, `--smoke-procedure-propagation`, `--smoke-procedure-duration`, `--smoke-delete-button`, `--smoke-window` или `--smoke-tutorial`. Профиль должен быть отдельным; некоторые сценарии запускаются по одному. При запуске Electron из среды Codex убирать переменную `ELECTRON_RUN_AS_NODE`, если она установлена.
- Пример PNG для README — `docs/images/schedule.png`, пересоздаётся вместе со скриншотами обучения.

## Автозаполнение

Генератор — `autofill.mjs` (без DOM, возвращает план: что удалить и что поставить), диалог и отчёт — конец `app.js`. Работает только на открытый день. Перебирает случайные раскладки до 500 мс и берёт лучшую: максимум поставленного, меньше выхода за конец дня, раньше окончание, меньше окон. Настройки — `stay.autofill`: `links`, `groupList` и `weekdays[0–6]`; новый день недели наследует последние использованные.

- **Справка:** презентация `autofillPages` по ⓘ в заголовке, короткие подсказки `AUTOFILL_HELP` у блоков, оба в `app.js`. При изменении правил обновлять и их, и скриншоты.
- **Режимы:** «Весь набор» заменяет всё незакреплённое у включённых пациентов. «На свободное место» заменяет незакреплённое только у выбранных процедур, остальное занимает время. Кнопка ↻ повторяет режим и настройки дня недели, без них открывает диалог. Запуск отменяется одним Ctrl+Z.
- **Замочек** только для генератора: назначение не двигается, занимает время и считается выполненным. Ручное редактирование не ограничено. Назначения, скрытые старой версией у выключенных пациентов, генератор не учитывает.
- **Правила:** все отмеченные процедуры всем включённым пациентам. У пациента и инструктора нет наложений. Инструкторы одной процедуры работают параллельно, пациенту нужна одна такая процедура; карточки с одинаковым названием считаются одной процедурой. Инструктор не возвращается к прежней процедуре. Время «с–до» у инструктора — жёсткое: что не влезло, в отчёте. Без «до» процедуры уходят за конец дня, но не дальше 24:00.
- **Максимум одновременно:** поле «Макс.» в строке ограничивает число пациентов на процедуре в один момент у всех инструкторов (например, кушеток две). Учитываются и закреплённые назначения; пусто — без ограничения.
- **Время:** «По сетке» — слоты от начала дня и заново от конца запрещённого периода; без сетки — любое время по шагу с перерывом у строки. Длительность не кратна шагу — генерация не запускается.
- **Связка** двух процедур: подряд, в любом порядке, у одного инструктора, не через запрещённый период. Флажок позволяет инструктору вести обе одновременно у разных пациентов. В частичном режиме партнёр добавляется сам.
- **Совместно:** «Совместно» или «По группам», до N пациентов, старт одновременно, один инструктор. Группа — именованный набор номеров по одному на пациента (`groupList: [{id,name,values}]`); пациенты в таблице групп идут по алфавиту. При «По группам» у строки выбирается группа; вместе идут пациенты с одинаковым номером, без номера — поодиночке. «Общая» есть всегда, изначально пустая, не удаляется и не переименовывается.
- **Ограничение:** настройки строк и связки привязаны к названию процедуры; при переименовании строка возвращается к умолчаниям, а связка отключается.
